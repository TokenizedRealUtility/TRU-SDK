Security architecture

No remote signer, no web-hosted WOTS private keys, no automatic rebroadcast.

What stays local

All WOTS+ keys, signer reservations and encrypted .pq01 state remain in your running Core process. This browser talks to a token-protected service bound to 127.0.0.1; the service contacts Core’s authenticated localhost RPC.

Wallet backups

Back up the encrypted main wallet, wallet seed, and the latest .pq01 sidecar together. For quantum signing, never restore an older sidecar or run two clones of the same WOTS keys. Keep this companion’s saved transaction directory private as well.

Tokens, NFTs and TRUScripts

Existing token, contract, marketplace and regular TRU wallet workflows are unchanged. Native quantum wallet RPC currently constructs one-input/one-output plain TRU transfers, not token transfers.

Activation and safety

Before activation, you can create, list, copy and back up descriptors, inspect node status and prepare the UI. Funds should only be sent through the post-activation, validated PQ01 transaction flow. Use a small test amount first and wait for confirmation.
